## 1. Фото: история, причина и решение

### 1.1. Хронология (коротко)

| Шаг | Что делали | Что узнали |
|---|---|---|
| 1 | Первый запуск | Серый круг вместо фото |
| 2 | В `errorBuilder` добавили debug-печать | `HTTP request failed, statusCode: 403` на адресе CDN `cdn.intra.42.fr` |
| 3 | Список запасных адресов (`medium`, `link`, `large`, `small`, `micro`) | Все пять дают 403: «файла нет» отпадает |
| 4 | Подмена `User-Agent` под браузер и проба тремя способами | 403 не изменился; страница ошибки с `nginx` (отказ отдаёт сервер за Cloudflare, а не антибот). `User-Agent` ни при чём |
| 5 | Опыты с браузерами | Chrome (залогинен в intra) открывает фото, **Samsung Internet и инкогнито Chrome на компьютере дают 403**. Моё промежуточное заключение «дело в IP или устройстве» было **неверным** (я приняла «браузер телефона» за Chrome, а это был Samsung Internet) |
| 6 | `curl` с компьютера кампуса | Без ничего: **403**. С `User-Agent` Chrome: **403**. **С заголовком `Authorization: Bearer <токен приложения>`: 200** |

### 1.2. Причина

CDN интры **закрыт авторизацией**, как и сам API. Запрос принимается, если к нему приложен токен (или cookies сессии интры, как у залогиненного браузера). Обычный `Image.network` ничего этого не прикладывает, поэтому получает `403`. Это политика сервиса, а не наша ошибка: те же 403 получают Samsung Internet и инкогнито.

Токен приложения (`client_credentials`) для этого годится: по результату `curl` CDN отдаёт фото именно с ним. Значит, способ получить фото честный и без входа пользователя: **скачать байты сами с заголовком `Authorization: Bearer …` и показать их через `Image.memory`**.

### 1.3. Решение

```text
ProfileScreen → ProfileAvatar → PhotoLoader.load(url) → TokenService (общий токен) → CDN → байты → Image.memory
```

- **`PhotoLoader`** (`lib/data/photo_loader.dart`): проверяет адрес, берёт общий токен, делает `GET` с `Authorization: Bearer`, разбирает коды ответа, кладёт успешные ответы в небольшой кэш в памяти (20 штук).
- **`ProfileAvatar`** принимает функцию `loadPhoto` (`PhotoFetcher`), пробует адреса из `imageUrls` по очереди, пока идёт загрузка показывает индикатор, при полной неудаче показывает заглушку с инициалами.
- Токен **один на всё приложение**: профиль и фото используют один `TokenService` (требование «не создавать токен на каждый запрос» соблюдено; тест `токен общий для профиля и фото: запрошен один раз`).

### 1.4. Безопасность: токен нельзя отправлять куда попало

Адрес фото приходит **из ответа сервера**, то есть это входные данные, которым нельзя доверять слепо. Если бы мы прикладывали токен к любому адресу, подмена адреса (теоретически, при взломе ответа или ошибке парсера) отправила бы наш токен постороннему серверу. Поэтому `PhotoLoader` пропускает только:

| Проверка | Отсекает |
|---|---|
| схема `https` | `http://…` (токен открытым текстом) |
| хост строго из списка `photoHosts` (`cdn.intra.42.fr`) | чужие хосты, поддомены вроде `cdn.intra.42.fr.evil.example.com` |
| `Uri.parse` разбирает адрес по правилам | трюк `https://cdn.intra.42.fr@evil.example.com/` (хост окажется `evil.example.com` и будет отклонён) |
| порт стандартный (443) | `https://cdn.intra.42.fr:8443/…` |
| путь не пустой | голый хост |

Всё это покрыто тестами (8 плохих адресов: токен не запрашивается и запрос не уходит). Дополнительно: тело ответа ограничено 5 МБ, пустое тело отклоняется, а в журнал попадает только хост и имя файла (без хеша каталога и без токена).

### 1.5. Что намеренно не сделано

- **Повтор с новым токеном при 401/403 от CDN.** Такой 403 может быть настоящим отказом, а каждая попытка обновить токен нарушала бы правило «не создавать токен на каждый запрос» (у нас пять адресов, это пять лишних токенов). Фото не критично, при неудаче просто заглушка. Недействительный токен всё равно обнаружит и заменит клиент API при следующем запросе профиля.
- **Дисковый кэш и `cached_network_image`.** Лишняя зависимость, а в памяти кэш уже есть.
- **Обход ограничений CDN** (подмена браузера, чужие прокси): не нужно, мы не обходим, а проходим авторизованным путём.

### 1.6. Чек-лист

1. `git pull`, `flutter analyze`, `flutter test` (ожидаю около **161**: прежние 137 + 19 тестов `PhotoLoader` + 5 тестов `ProfileAvatar`).
2. Запуск на телефоне: на экране профиля должно появиться фото (круг). В журнале строка вида `GET cdn.intra.42.fr/…/medium_vdarsuye.png → 200, N байт, M мс`.
3. Если снова нет фото, пришли строку `Фото не загрузилось (…)` из журнала целиком.

## 2. Локализация: теория

**Локализация** (l10n, «l», десять букв, «n») это перевод интерфейса и форматов под язык и регион. **Интернационализация** (i18n) это подготовка кода к тому, чтобы переводы вообще можно было подключать. Главное правило: **в коде нет «зашитых» фраз для пользователя**. Вместо `Text('Buscar')` пишется `Text(strings.searchButton)`, а где-то отдельно лежит таблица «ключ → фраза на каждом языке».

Откуда Flutter знает язык: из настроек телефона (`Locale('es', 'ES')`, язык + страна). `MaterialApp` получает список поддерживаемых языков (`supportedLocales`) и **сам** выбирает подходящий:

1. точное совпадение (`es_ES` с `es_ES`);
2. совпадение по языку (`es_MX` → `es`);
3. иначе **первый язык в списке**.

Пункт 3 даёт нам нужное поведение: испанский стоит первым, значит русский, немецкий и любой другой телефон получат испанский.

Отдельно существуют **делегаты** (`LocalizationsDelegate`): объекты, которые по `Locale` загружают словарь. У Flutter есть свои делегаты для собственных виджетов (подсказка «Назад», названия месяцев, меню «Копировать»), они живут в пакете `flutter_localizations`. Без них при испанском языке Material-виджеты упадут с ошибкой «No MaterialLocalizations found», потому что встроенные английские тексты есть только для английского.

## 3. Как выбран подход и альтернативы

| Подход | Плюсы | Минусы | Вывод |
|---|---|---|---|
| **`AppStrings` вручную: абстрактный класс + по классу на язык (наш)** | Без кодогенерации. Компилятор проверяет, что перевод есть на каждом языке. Всё читается глазами. Легко тестировать | Пока языков два, это ок; на 10 языков громоздко. Нет автоматической обработки множественного числа | Выбрано |
| Официальный `gen-l10n` + файлы `.arb` (пакет `intl`) | Стандарт Flutter, поддержка множественного числа и дат, удобно отдавать файлы переводчикам | Код генерируется командой; в разных версиях Flutter меняются настройки (`synthetic-package`, папка вывода); я не могу запустить генератор у себя и проверить | Лучший вариант для большого проекта. Нам рискованно вслепую |
| `easy_localization` | Простой API, переводы из JSON | Сторонняя библиотека (нужно обосновывать на защите), строковые ключи без проверки компилятором | Лишняя зависимость |
| `Map<String, String>` в одном файле | Совсем просто | Опечатка в ключе обнаружится только во время работы | Хрупко |

**Если захочешь перейти на `gen-l10n` позже:** все фразы уже собраны в одном месте (`app_strings.dart`), переезд будет механическим.

Зависимость, которую мы добавили: `flutter_localizations` (в `pubspec.yaml`, `sdk: flutter`). Она входит в Flutter SDK, отдельной версии нет, поэтому обосновывать на защите почти нечего: «стандартные переводы виджетов от самой Flutter».

## 4. Как это устроено у нас

```text
lib/l10n/
├── app_strings.dart       абстрактный «словарь», делегат, список языков
├── app_strings_es.dart    испанский (Испания), язык по умолчанию
└── app_strings_en.dart    английский
```

**Использование в виджете:**

```dart
final strings = AppStrings.of(context);
Text(strings.searchButton)          // 'Buscar' или 'Search'
```

`AppStrings.of(context)` работает как `Theme.of(context)`: ищет вверх по дереву ближайший `Localizations`, который создал `MaterialApp` по нашим `localizationsDelegates`.

**Исчерпывающие `switch` в словаре.** Двух видов:

```dart
String errorText(ApiException error) => switch (error) { ... };       // по sealed-классу
String loginProblemText(LoginProblem problem) => switch (problem) { ... };  // по enum
```

Добавишь новую ошибку, и без перевода проект не соберётся. Добавишь абстрактный геттер в `AppStrings`, и без реализации в `AppStringsEs` и `AppStringsEn` тоже.

**`SynchronousFuture`.** Делегат обязан вернуть `Future`, но наши тексты уже в памяти. `SynchronousFuture` это «будущее», которое готово сразу, поэтому первый кадр рисуется без мигания.

## 5. Что пришлось поменять в старом коде и почему

Раньше тексты ошибок были зашиты внутрь `ApiException` и `validateLogin`, и по-русски. Перевод так не сделать (язык известен только интерфейсу, а у ядра нет `context`). Поэтому разделили «что случилось» и «как об этом сказать»:

| Было | Стало | Зачем |
|---|---|---|
| `validateLogin` возвращал строку `'Введите логин'` | Возвращает `LoginProblem.empty` / `invalidChars` (enum) или `null` | Ядро говорит *что* не так, а текст выбирает интерфейс |
| Таймаут отличался от обрыва сети только текстом | `NetworkException.isTimeout` | Надо различать их без разбора строки |
| `ErrorBanner` брал `error.message` | Берёт `AppStrings.of(context).errorText(error)` | Язык ошибки совпадает с языком интерфейса |
| `ApiException.message` показывался пользователю | Остался как **описание для разработчика** (логи, тесты) | Старые тесты и отладка продолжают работать |
| `ConfigException` с готовым русским текстом | Добавлено поле `missing` (список имён), а `ConfigErrorApp` получает его и сам подбирает фразу | Экран ошибки конфигурации тоже на нужном языке |
| `ConfigErrorApp(message: …)` | `ConfigErrorApp(missingKeys: …, unreadable: …)` | См. выше |

Подсказка на будущее: если ядру нужно сообщить интерфейсу о проблеме, возвращай **данные** (enum, sealed-класс, поле), а не готовую фразу.

## 7. Ловушки

| Ловушка | Что видишь | Решение |
|---|---|---|
| Не подключить `GlobalMaterialLocalizations.delegate` | Красный экран «No MaterialLocalizations found» при испанском | Подключено через `AppStrings.localizationsDelegates` |
| Забыть `flutter_localizations` в `pubspec.yaml` | Ошибка импорта | Добавлено. После правки: `flutter pub get` |
| В тестах язык «сам» выбирается английским | Тесты проходят только при английской системе | Все тесты виджетов идут через `testApp(..., locale: es)` |
| Склейка фраз кусочками (`'Hay ' + n + ' resultados'`) | В других языках порядок слов другой | Для фраз с вставками делай метод с параметром (`retryAfterHint(int seconds)`) |
| `tester.pageBack()` в тестах при испанском языке | `One back button expected on screen`, найдено 0 | `pageBack` ищет кнопку по подсказке `'Back'`, а по-испански она `'Atrás'` | Нажимать `find.byTooltip('Atrás')` (заодно это проверяет, что переводы Flutter подключены). Это моя ошибка, 1 тест из 130 |
| Склеивать ошибку из двух переводов | Смешанные языки | `errorText` собирает всю фразу внутри одного словаря |
| Править `.env`-шаблон или логи в расчёте, что они переведены | Не переведены | Логи и описания для разработчика остаются русскими (раздел 8) |
| Название «Swifty Companion» | Не переводится | Одинаково в обоих словарях |

## 8. Что остаётся на русском

- Вся документация (договорённость проекта).
- Отладочный журнал (`Получен токен…`, `GET …`, `Фото не загрузилось…`), он только для разработчика и только в debug.
- `ApiException.message` и `ConfigException.message`: описание для разработчика и тестов.
- Комментарии в коде.

Пользователь видит только испанский или английский. Если когда-нибудь понадобится русский интерфейс, это один новый файл `app_strings_ru.dart` и пара строк в списке языков.
