## 1. Из чего состоит Flutter-проект и из чего наш

### 1.1. Стандартные части

| Что | Для чего |
|---|---|
| `lib/` | весь Dart-код приложения, `lib/main.dart` это точка входа |
| `android/` (`ios/`, `web/`...) | нативные «обёртки»: манифест, Gradle, `MainActivity` |
| `test/` | автотесты |
| `pubspec.yaml` | имя, версия, зависимости, ассеты |
| `pubspec.lock` | точные версии зависимостей |
| `analysis_options.yaml` | правила линтера |
| `assets/` | картинки и шрифты |
| `build/`, `.dart_tool/` | генерируется, в git не идёт |

У нас платформа одна, `android/` (папку `ios/` мы не создавали).

### 1.2. Как структурируют `lib/`

Flutter ничего не навязывает, структуру выбирает команда.

| Подход | Идея | Плюс | Минус |
|---|---|---|---|
| Всё в `main.dart` | один файл | быстро для прототипа | не масштабируется |
| **По слоям (наш)** | `core`, `data`, `models`, `ui` | просто, границы видны | в большом проекте фичи размазаны |
| По фичам | `features/search`, `features/profile` | удобно большим командам | для двух экранов избыточно |
| Clean Architecture | domain / data / presentation + интерфейсы | идеальная тестируемость | много церемоний |
| Provider, Riverpod, Bloc | отдельный слой состояния | масштабируется | лишняя зависимость; нам хватает `setState` |

### 1.3. Наша структура

```
lib/
├── main.dart                точка входа, сборка зависимостей
├── core/                    не знает про экраны
│   ├── config.dart, api_constants.dart        конфиг (.env) и константы
│   ├── token_service.dart                     OAuth2: кэш токена, single-flight
│   ├── api_client.dart, http_helpers.dart     HTTP: заголовки, повтор после 401, таймаут
│   ├── api_exception.dart                     sealed-семейство ошибок
│   ├── json_reader.dart                       безопасное чтение JSON
│   ├── login.dart                             нормализация и валидация логина
│   └── display.dart                           «N/A», форматирование
├── data/                    превращает сеть в объекты
│   ├── user_repository.dart                   логин → UserProfile
│   └── photo_loader.dart                      фото с токеном и белым списком хостов
├── models/                  предметная область: UserProfile, Skill, ProjectResult...
├── l10n/                    тексты (es, en)
└── ui/                      экраны и оформление (ui/steampunk это «красота»)
```

### 1.4. Правило зависимостей

```
ui  →  data  →  core
 ↓      ↓
  models (чистые данные)
```

Стрелки идут вниз, нижний слой не импортирует верхний. Поменяешь API, экраны не трогаешь; поменяешь вид, сеть не трогаешь. `core` и `models` проверяются тестами без интерфейса.

Объекты собираются в `main.dart` и передаются **через конструкторы** (внедрение зависимостей вручную):

```
AppConfig ─► TokenService ─► ApiClient ─► UserRepository ─► SearchScreen
                   └──────► PhotoLoader ─────────────────────► ProfileScreen
```

Один `TokenService` на всё приложение, поэтому токен общий. В тестах вместо настоящего клиента подставляется `MockClient`.

### 1.5. Что нестандартного

- Состояние только через `setState`, без Provider и Bloc (экранов два, библиотека потребовала бы обоснования).
- Тексты вручную (`l10n/`, два языка), без генератора `intl`: меньше зависимостей, меньше возможностей.
- Около 40 % кода это оформление (`ui/steampunk`, заставка). Это сверх задания, и на защите про него надо говорить честно.

## 2. Точка входа и запуск по шагам

В `lib/main.dart` есть обычная `Future<void> main()`. Но до неё есть ещё два уровня:

| Уровень | Где | Что делает |
|---|---|---|
| Android | `AndroidManifest.xml`: у `MainActivity` стоят `MAIN` и `LAUNCHER` | «этот экран запускается по иконке» |
| Нативная обвязка | `MainActivity.kt`: `class MainActivity : FlutterActivity()` | поднимает движок Flutter |
| Dart | `main()` в `lib/main.dart` | готовит зависимости и вызывает `runApp` |

**Инверсия управления.** В C ты сам пишешь цикл. Во Flutter твоя `main()` только собирает объекты и отдаёт управление фреймворку через `runApp`; дальше цикл событий крутит фреймворк и вызывает твои обработчики.

```
тап по иконке
 → Android запускает процесс и MainActivity (LAUNCHER)
 → пока движок стартует, система показывает свою заставку (splash Android 12+)
 → FlutterActivity создаёт движок, загружает нативную библиотеку и Dart-код
 → движок вызывает main()
 → WidgetsFlutterBinding.ensureInitialized()    связь с движком готова
 → dotenv.load('.env')                           читаем ассет из APK
 → AppConfig.fromMap(...)                        проверка FT_UID, FT_SECRET
       нет ключей → runApp(ConfigErrorApp)
 → _buildDependencies: TokenService → ApiClient → UserRepository, PhotoLoader
 → runApp(SwiftyApp) → MaterialApp → SplashScreen → SearchScreen
 → дальше работают обработчики событий
```

`ensureInitialized` нужен потому, что до `runApp` мы читаем `.env` через платформенный код: вызов гарантирует, что мост между Dart и движком готов.

Разрешение `INTERNET` в манифесте обязательно: без него Android молча блокирует сеть. В debug-манифесте оно есть по умолчанию, в release его нужно объявить явно.

## 3. Как .dart-файлы знают друг о друге

Заголовков нет, нет `#include` и нет отдельной линковки.

| C | Dart |
|---|---|
| `#include "x.h"` **вставляет текст** | `import 'x.dart';` **подключает имена**, текст не копируется |
| объявление в `.h`, реализация в `.c` | один файл |
| порядок объявлений важен | на верхнем уровне порядок не важен |
| защита от двойного включения | не нужна |
| `static` скрывает имя от других файлов | имя с `_` скрывает от других файлов |
| раздельная компиляция + линковщик | компилятор берёт всю программу |

```dart
import '../core/login.dart';                  // относительный путь
import 'package:flutter/material.dart';        // пакет
import 'package:http/http.dart' as http;       // с псевдонимом
```

- Каждый файл это **библиотека**. Всё, что объявлено на верхнем уровне и не начинается с `_`, видно импортирующим.
- **Приватность на уровне файла, а не класса** (отличие от C++ и Java): `_loginPattern`, `_SearchScreenState` доступны только внутри своего файла.
- `package:swifty_companion/...`: имя пакета берётся из `pubspec.yaml`. Где пакет лежит физически, знает `.dart_tool/package_config.json` (создаёт `flutter pub get`).
- `as http` даёт префикс, чтобы имена не конфликтовали.
- `show` и `hide` берут из файла часть имён или исключают часть; `export` отдаёт имена другого файла дальше. У нас почти не нужны.
- Компилятор идёт по цепочке импортов **от `main.dart`**; всё, до чего он не дошёл, в приложение не попадает. Неиспользуемый код дополнительно вырезается в release (tree shaking). Анализатор при этом проверяет все файлы `lib/`.
- Циклические импорты Dart разрешает, но это запах: слои перемешаны. У нас циклов нет.

## 4. `json_reader.dart`: чтение JSON без падений

**Проблема.** После `jsonDecode` данные имеют тип `dynamic`. Запись `json['level'] as double` упадёт, если сервер вернул `null`, строку или целое. Задание требует обрабатывать все случаи ошибок, а ответ API мы не контролируем. Правило: **одно кривое поле не должно ронять весь профиль**.

Схема каждой функции: проверь тип; подходит, верни значение; не подходит, верни `null` (или пустой список).

| Функция | Возвращает | Нюанс |
|---|---|---|
| `readString` | `String?` | `null`, пустая строка, пробелы и `"hidden"` (любой регистр) дают `null`; целое число превращается в строку |
| `readDouble` | `double?` | `0` и `0.0` оба становятся `double`; `NaN` и бесконечность отвергаются |
| `readInt` | `int?` | дробное округляется, строка отвергается |
| `readBool` | `bool?` | только настоящий `true` или `false` |
| `readMap` | `Map<String, dynamic>?` | принимает и неточно типизированный `Map`, копирует его |
| `readList` | `List` | если не список, возвращает **пустой** (проще итерировать) |
| `readDate` | `DateTime?` | ISO 8601 через `tryParse`, мусор даёт `null` |
| `readObjects<T>` | `List<T>` | элементы-не-объекты **молча пропускаются** |

**`"hidden"`.** Интра для скрытых данных (например, `phone`) может отдать строку `"hidden"`. Все три «пустых» случая (`null`, `""`, `"hidden"`) сводятся к `null`, остальной код не различает, как именно пришло «пусто». Побочный эффект: человек со скрытым телефоном неотличим от человека без телефона; для приложения это правильно.

**Риски и компромиссы.**
- Молчаливый пропуск кривых элементов это выбор устойчивости вместо строгости: для учебного приложения верно, для медицинского было бы наоборот.
- `null` не говорит, **почему** данных нет (скрыто, нет в API или поломка).

**Альтернативы:** сгенерированные модели (`json_serializable`, `freezed`; лишние зависимости и кодогенерация, зато меньше ручного кода), `as`-приведение с `try/catch` (громоздко и роняет весь объект).

`readObjects<T>(value, parse)` дженерик: `T` подставляется при вызове, как шаблон в C++. Пример: `readObjects(json['skills'], Skill.fromJson)`.

## 5. `display.dart`: от значений к тексту

| Что | Для чего |
|---|---|
| `notAvailable = 'N/A'` | единый текст для отсутствующих данных (privacy из задания) |
| `orNA` | расширение: `value.orNA` даёт текст значения или `N/A` для `null` |
| `initialsOf(name)` | инициалы для заглушки вместо фото |
| `levelFraction(level)` | дробная часть уровня как доля пути до следующего (`9.63` даёт `0.63`) |
| `formatDate` | `2024-03-01`, одинаково на любом языке и в любом часовом поясе |
| `formatLevel` | два знака: `9.63`, `3.00` |
| `formatPercent` | процент целым: `48 %` |

- `extension NotAvailableX on Object?` добавляет метод `orNA` любому объекту, включая `null`; можно писать `profile.email.orNA`. Ближайшая аналогия в C++: свободная функция, которая выглядит как метод.
- `formatDate` берёт `year`, `month`, `day` из самого значения и не переводит во «местное время»: иначе дата могла бы съехать на день в зависимости от часового пояса телефона.

**Сквозной пример:**

```
сервер: "phone": "hidden"
   │  readString              → null      (core/json_reader.dart)
   ▼
UserProfile.phone = null      (models/user_profile.dart)
   │  profile.phone.orNA      → "N/A"     (core/display.dart)
   ▼
экран: «Teléfono: N/A»
```

## 6. Строки в Dart: кодовые единицы, руны, графемы

Строка в Dart хранится как последовательность **UTF-16 кодовых единиц** (по 16 бит). Символ, не помещающийся в 16 бит (например, эмодзи), занимает **две** единицы (суррогатная пара).

| Что | Как получить | Что это |
|---|---|---|
| кодовая единица UTF-16 | `s[0]`, `s.length`, `s.codeUnits` | кусок по 16 бит, может быть половиной символа |
| **руна** | `s.runes` | один Unicode-символ целиком (кодовая точка) |
| графема | пакет `characters` | то, что человек видит как «один символ» |

```dart
final s = '😀Bob';
s.length;                           // 5, а не 4
s[0];                               // половина эмодзи: мусор
String.fromCharCode(s.runes.first)  // '😀' целиком
```

`initialsOf` берёт `runes.first`, чтобы не разрезать символ пополам.

**Ограничение.** Руна это ещё не «символ глазами человека»: «é», записанная как «e» плюс комбинируемый акцент, это две руны, и мы возьмём только «e». Эмодзи с оттенком кожи тоже состоят из нескольких рун. Полностью это решает пакет `characters` (разбивает по графемам), но для инициалов в профиле это перебор, а лишняя зависимость требует обоснования.

Заодно: в Dart `toLowerCase()` не зависит от языка телефона. Это важно для `normalizeLogin`.

## 7. Ленивые конвейеры: `split().where().take()`

```dart
final words = name.split(RegExp(r'\s+')).where((w) => w.isNotEmpty).take(2);
```

Пример: `name = "  Jane   Doe Smith "`.

1. `split(RegExp(r'\s+'))`. `r'...'` это «сырая» строка (обратная косая черта не экранирует). `\s` любой пробельный символ, `+` «один или больше подряд». Если строка начинается или заканчивается разделителем, на краю остаётся пустая строка: `["", "Jane", "Doe", "Smith", ""]`.
2. `.where((w) => w.isNotEmpty)` фильтр; `(w) => ...` анонимная функция (лямбда). Остаётся `["Jane", "Doe", "Smith"]`.
3. `.take(2)` первые два: `["Jane", "Doe"]`.

Дальше `.map(...)` (первая руна в верхнем регистре) и `.join()` дают `"JD"`.

| Вход | Результат |
|---|---|
| `Jane Doe` | `JD` |
| `madonna` | `M` |
| `Jean-Luc Picard` | `JP` (дефис не разделяет слова) |
| `""`, `"   "` | пустая строка |

**Ленивость.** `where` и `take` возвращают `Iterable`, то есть «рецепт вычисления», который выполняется только при обходе (в `.map(...).join()`). Если обойти `words` дважды, конвейер выполнится дважды; у нас обход один. Аналог в C++20: `views::filter` и `views::take`. `name.trim().split(...)` не избавил бы от `.where`: пустая строка после `trim` всё равно даёт `[""]`.

## 8. `config.dart`, `api_constants.dart`, `api_exception.dart`

### 8.1. `config.dart` (46 строк)

- `ConfigException(message, missing)`: ошибка конфигурации. `missing` это список имён переменных, которых не хватает; экран ошибки показывает перевод.
- `AppConfig`: пара `clientId` и `clientSecret`.
- `AppConfig.fromMap(Map<String, String> env)` принимает **обычный словарь**, а не `dotenv` напрямую. Поэтому проверяется тестами без Flutter и без настоящего `.env`. Значения обрезаются (`trim`), пустые считаются отсутствующими; если чего-то нет, бросается `ConfigException` со списком недостающих ключей.
- `toString()` переопределён и скрывает значения (`***`): секрет не попадёт в лог через `print(config)`.

Риск: `.env` объявлен ассетом, поэтому **секрет внутри APK**. Альтернатива: переменные `--dart-define` при сборке (секрет тоже вшивается), либо свой бэкенд-прокси (правильно для продакшена, для задания избыточно).

### 8.2. `api_constants.dart` (7 строк)

- `apiHost = 'api.intra.42.fr'`: хост без схемы; `https` задаётся при сборке адреса, поэтому «случайного `http`» не будет.
- `photoHosts = {'cdn.intra.42.fr'}`: **белый список** хостов, на которые разрешено отправлять токен вместе с запросом фото. Адрес фото приходит из ответа сервера, ему нельзя доверять слепо: иначе подставной чужой адрес получил бы наш токен.

### 8.3. `api_exception.dart` (64 строки)

Все ошибки API в одном **закрытом (`sealed`) семействе**: подклассы объявлены только в этом файле, поэтому компилятор знает полный список и требует учесть каждый случай в `switch`. Забыть обработать новый вид ошибки не получится.

| Класс | Когда | Особенность |
|---|---|---|
| `NetworkException` | нет сети, DNS, таймаут | `isTimeout` выбирает текст «нет сети» или «сервер не ответил вовремя» |
| `AuthException` | неверные ключи, токен отвергнут | повторять бессмысленно |
| `NotFoundException` | HTTP 404 | логин не найден |
| `RateLimitException` | HTTP 429 | `retryAfter` из заголовка, если сервер сказал |
| `ServerException` | HTTP 5xx | сервер сломан |
| `UnexpectedResponseException` | ответ не такой, как ожидали | не JSON, нет полей, странный код |

- Поле `message` это текст **для разработчика** (логи, тесты). Пользователю показывается перевод из `AppStrings.errorText`: язык ошибки совпадает с языком интерфейса.
- В `switch` по `sealed` используются **паттерны объектов**: `NetworkException(isTimeout: true) => ...`, `RateLimitException(:final retryAfter) => ...`.

**Почему не `Exception('текст')`.** Тогда экран различал бы ошибки по тексту, что хрупко. С типами различие проверяет компилятор.

## 9. Вопросы, которые могут задать

| Вопрос | Ответ в одну фразу |
|---|---|
| Где точка входа? | `main()` в `lib/main.dart`, под ней `MainActivity`. |
| Что делает `runApp`? | Делает корневой виджет и передаёт управление фреймворку. |
| Как файлы видят друг друга? | Через `import`: это подключение имён, а не вставка текста. |
| Как скрыть деталь реализации? | Имя с `_` приватно для файла. |
| Что будет, если API вернёт строку вместо числа? | `readDouble` вернёт `null`, поле покажет `N/A`, приложение не упадёт. |
| Что значит `hidden`? | Так интра помечает скрытое; приводим к `null` и показываем `N/A`. |
| Зачем `sealed` для ошибок? | Компилятор заставит обработать каждый вид ошибки. |

| Почему `runes.first`, а не `[0]`? | Чтобы не разрезать символ из двух кодовых единиц пополам. |
