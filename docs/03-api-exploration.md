## 2. Теория: OAuth2 и client credentials

### 2.1 Что такое OAuth2

**OAuth2** это стандарт, по которому приложение получает доступ к данным сервиса, не зная пароля пользователя. Вместо пароля используется **токен доступа** (`access_token`): строка, которая сервер выдаёт приложению и которую приложение прикладывает к каждому запросу.

Участники:

| Роль | У нас |
|---|---|
| **Клиент** (приложение) | наше приложение Swifty Companion |
| **Сервер авторизации** | выдаёт токены: `https://api.intra.42.fr/oauth/token` |
| **Сервер ресурсов** | отдаёт данные: `https://api.intra.42.fr/v2/...` |

### 2.2 Какой «поток» (flow) мы используем

В OAuth2 есть несколько потоков. Нам нужен **Client Credentials**:

- Приложение доказывает свою личность **само**, парой `UID` и `SECRET`, которые мы получили при регистрации в интре.
- **Входа пользователя нет**, и токен **не привязан ни к какому студенту**. Поэтому доступны **только публичные данные** (`scope` равен `public`).

Другой поток, **Authorization Code**, нужен, когда пользователь входит в приложение через интру. Тогда используется Redirect URI. Для нашего задания это не требуется, поэтому при регистрации мы указали заглушку.

### 2.3 Как выглядит работа

1. Приложение отправляет серверу авторизации запрос `POST /oauth/token` с параметрами `grant_type=client_credentials`, `client_id` и `client_secret`.
2. Сервер отвечает JSON с токеном и сроком жизни. В официальном гайде пример токена живёт **7200 секунд (2 часа)**.
3. Для данных приложение шлёт `GET /v2/...` с заголовком `Authorization: Bearer <токен>`.
4. Когда срок истёк, сервер отвечает ошибкой `401`, и нужен новый токен.

### 2.4 Почему «один токен на сессию»

Требование задания «не создавай токен на каждый запрос» разумно: запрос токена это отдельный сетевой вызов, у API есть лимиты частоты запросов, и лишние обращения тратят их впустую. Правильная схема: получить токен один раз, хранить в памяти вместе со временем истечения и использовать до тех пор, пока он не протух. Это и есть наш будущий токен-сервис, а обновление по истечении это бонус.

### 2.5 Коды ответа HTTP, которые нам встретятся

| Код | Значение | Что делать приложению |
|---|---|---|
| `200` | Всё хорошо | Разобрать JSON |
| `401` | Токен недействителен или истёк | Один раз запросить новый токен и повторить |
| `404` | Такого логина нет | Сообщение «логин не найден» |
| `429` | Слишком много запросов | Подождать, показать сообщение |
| `5xx` | Ошибка на стороне сервера | Сообщение «сервис недоступен» |

## 3. Подготовка: файл .env

В корне проекта лежит файл `.env` (в git он не попадает, см. [02](02-git-and-secrets.md)). Формат:

```text
FT_UID=значение
FT_SECRET=значение
```

Без кавычек и без пробелов вокруг `=`. Закрой его от других пользователей машины (кампус общий):

```bash
chmod 600 .env
```

`600` значит: читать и писать может только владелец.

**Ловушка с именем `UID` (устранена).** Скрипты ниже читают `.env` через `grep` и `cut`, а не командой `source .env`. Изначально переменная называлась `UID`, а `UID` в zsh и bash это встроенная переменная (номер пользователя), **только для чтения**: присвоение даёт ошибку вроде `read-only variable: UID`. Теперь переменные называются `FT_UID` и `FT_SECRET`, и конфликта нет. Чтение через `grep` оставлено сознательно: значения не попадают в окружение оболочки.

## 4. Скрипт 1. Получение токена

```bash
RESP=$(curl -s -X POST https://api.intra.42.fr/oauth/token \
  -d grant_type=client_credentials \
  -d client_id="$(grep '^FT_UID=' .env | cut -d= -f2-)" \
  -d client_secret="$(grep '^FT_SECRET=' .env | cut -d= -f2-)")
printf '%s' "$RESP" | python3 -c 'import sys,json; d=json.load(sys.stdin); d.pop("access_token",None); print(json.dumps(d,indent=2))'
```

### 4.1 Разбор построчно

**`RESP=$( ... )`** это *подстановка команды*: оболочка выполняет всё внутри скобок и **сохраняет вывод в переменную** `RESP`, а не печатает его. Токен при этом не появляется на экране.

**`curl -s -X POST https://api.intra.42.fr/oauth/token`**
- `curl` консольная утилита для HTTP-запросов.
- `-s` (silent) отключает индикатор прогресса, чтобы в переменную попал только ответ.
- `-X POST` задаёт метод запроса. (С флагом `-d` curl и так выбирает POST, так что здесь это для ясности.)

**`\` в конце строки** переносит команду на следующую строку. Это должен быть последний символ строки, иначе перенос не сработает.

**`-d grant_type=client_credentials`** флаг `-d` (data) добавляет параметр в тело запроса в формате формы (`application/x-www-form-urlencoded`). Этим параметром мы говорим серверу, какой поток используем.

**`-d client_id="$(grep '^FT_UID=' .env | cut -d= -f2-)"`** самое важное место:
- `grep '^FT_UID=' .env` выводит из файла строку, которая **начинается** (`^`) с `FT_UID=`.
- `|` (конвейер) передаёт этот вывод следующей команде.
- `cut -d= -f2-` разрезает строку по символу `=` (`-d=`) и берёт **всё, начиная со 2-го поля** (`-f2-`). Дефис после двойки нужен, чтобы значения, содержащие `=`, не обрезались.
- `$( ... )` подставляет результат в команду, а внешние кавычки `"..."` защищают значение от разбиения по пробелам и раскрытия шаблонов.

То же самое делает следующая строка для `FT_SECRET`.

**Почему так, а не `source .env`:** значения не попадают ни в окружение оболочки, ни в историю команд (история хранит текст команды, а не подставленные значения), а `source` заодно не нужен.

**`printf '%s' "$RESP" | python3 -c '...'`**
- `printf '%s' "$RESP"` печатает содержимое переменной как есть. Вместо `echo` используем `printf`: в zsh `echo` по умолчанию **интерпретирует обратные слэши** (`\n`, `\"` и т. п.), что может испортить JSON.
- `|` передаёт текст на вход Python.
- `python3 -c '...'` выполняет строку как программу. Внутри:
  - `import sys,json` подключает модули стандартной библиотеки.
  - `d=json.load(sys.stdin)` читает JSON со стандартного ввода и превращает его в словарь Python.
  - `d.pop("access_token",None)` **удаляет** ключ `access_token` (второй аргумент `None` значит «если ключа нет, ошибки не будет»). Токен нам на экране не нужен.
  - `print(json.dumps(d,indent=2))` печатает словарь как красиво отформатированный JSON с отступом в 2 пробела.

### 4.2 Как выглядит результат

Типичный вид (по описанию в официальном гайде; значения условные, набор полей может отличаться):

```json
{
  "token_type": "bearer",
  "expires_in": 7200,
  "scope": "public",
  "created_at": 1700000000
}
```

Что здесь важно: `token_type` (тип токена), `expires_in` (срок жизни в секундах), `scope` (область доступа), `created_at` (когда создан, время Unix).

### 4.3 Если что-то не так

| Симптом | Вероятная причина | Что проверить |
|---|---|---|
| `invalid_client` | Неверные UID или SECRET | Лишний пробел, кавычки в `.env`, недокопированная строка |
| Пустой ответ | Нет сети или заблокирован доступ | `curl -s -o /dev/null -w '%{http_code}\n' https://api.intra.42.fr/` |
| `python3: command not found` | Нет Python | Вместо последней строки: `printf '%s' "$RESP" \| sed 's/"access_token":"[^"]*"/"access_token":"***"/'` |
| Ошибка разбора JSON | Ответ не JSON (например, страница ошибки) | Посмотреть сырой ответ: `printf '%s' "$RESP" \| head -c 300` (осторожно: токен виден) |

### 4.4 Достать токен в переменную

```bash
TOKEN=$(printf '%s' "$RESP" | python3 -c 'import sys,json; print(json.load(sys.stdin)["access_token"])')
[ -n "$TOKEN" ] && echo "токен получен"
```

- `json.load(sys.stdin)["access_token"]` берёт значение по ключу (в отличие от `pop`, здесь ошибка, если ключа нет).
- `[ -n "$TOKEN" ]` проверяет, что строка **не пустая** (`-n` значит *non-zero length*).
- `&&` выполняет `echo` только если проверка прошла успешно.

Токен живёт **только в памяти этого терминала**. Закрыл терминал, и он пропал; через ~2 часа он протухнет. Ни в файл, ни в чат его не записывай.

### 4.5 Риски и ограничения

- **Список процессов.** Пока работает `curl`, его аргументы (в том числе UID и SECRET) **видны другим пользователям той же машины** через `ps`. Для учёбы это приемлемо, но знать об этом нужно. Альтернатива: отправлять тело запроса через стандартный ввод: `printf 'grant_type=...&client_id=...&client_secret=...' | curl -s -X POST URL -d @-`. Так значения не попадают в аргументы процесса (`printf` встроен в оболочку).
- **Токен тоже учётные данные**, пусть и временные и только с публичным доступом. В чат и в коммиты его не кладём.

## 5. Скрипт 2. Запрос профиля и сохранение в файл

```bash
mkdir -p ~/goinfre/swifty_samples
curl -s -w 'HTTP %{http_code}\n' -H "Authorization: Bearer $TOKEN" \
  "https://api.intra.42.fr/v2/users/<логин>" -o ~/goinfre/swifty_samples/user.json
chmod 600 ~/goinfre/swifty_samples/user.json
```

(вместо `<логин>` подставь логин студента)

### 5.1 Разбор

- **`mkdir -p ~/goinfre/swifty_samples`** создаёт папку для образцов. Флаг `-p` означает «не ругаться, если уже есть, и создавать вложенные папки».
- **`-w 'HTTP %{http_code}\n'`** (write-out) после завершения запроса печатает заданный формат. `%{http_code}` подставляет код ответа сервера (200, 401, 404, ...). Это единственное, что появится в консоли: тело ответа мы отправили в файл.
- **`-H "Authorization: Bearer $TOKEN"`** добавляет заголовок. По нему сервер узнаёт, что запрос идёт от нашего приложения.
- **`"https://api.intra.42.fr/v2/users/<логин>"`** адрес ресурса: данные пользователя по логину.
- **`-o ~/goinfre/swifty_samples/user.json`** (output) сохраняет тело ответа в файл вместо вывода на экран.
- **`chmod 600`** закрывает файл от других пользователей.

### 5.2 Почему файл лежит вне репозитория

В ответе **личные данные студента** (почта, телефон и т. п.). Если сохранить его в папку проекта, его легко случайно закоммитить. Каталог `goinfre` не связан с git, поэтому такой образец безопасен. Цена: `goinfre` периодически чистится, и образец придётся запросить заново (это секунда).

### 5.3 Запрос для чужого логина

Менять нужно только логин в адресе. Для проверки обработки ошибок удобно подставить несуществующий логин (должен прийти `404`) и испорченный токен (должен прийти `401`).

## 6. Скрипт 3. Структура JSON без значений

```bash
python3 - <<'EOF'
import json, os
d = json.load(open(os.path.expanduser("~/goinfre/swifty_samples/user.json")))
for k, v in d.items():
    if isinstance(v, list) and v and isinstance(v[0], dict):
        print(f"{k}: list[{len(v)}] of dict, keys={sorted(v[0].keys())}")
    elif isinstance(v, dict):
        print(f"{k}: dict, keys={sorted(v.keys())}")
    else:
        print(f"{k}: {type(v).__name__}")
EOF
```

### 6.1 Разбор

**`python3 - <<'EOF' ... EOF`** запуск программы, написанной прямо в терминале:
- `-` значит «читай программу со стандартного ввода».
- `<<'EOF'` это *here-document*: всё до строки `EOF` подаётся как ввод.
- **Кавычки вокруг `EOF` важны**: они отключают подстановки оболочки внутри блока (`$`, обратные кавычки, `\` остаются как есть). Без них оболочка начала бы «раскрывать» кусочки твоего кода.

**`json.load(open(os.path.expanduser("~/goinfre/...")))`**
- `os.path.expanduser` заменяет `~` на домашнюю папку: сам Python тильду не раскрывает, это делает оболочка, а мы внутри Python.
- `open(...)` открывает файл, `json.load(...)` читает его и превращает JSON в словарь.

**`for k, v in d.items():`** перебирает все пары «ключ и значение» верхнего уровня.

**`isinstance(v, list) and v and isinstance(v[0], dict)`** три проверки подряд: это список, он **не пуст** (`v` в логическом контексте ложно для пустого списка, благодаря этому не будет ошибки при обращении к `v[0]`), и его первый элемент словарь. Тогда печатаем количество элементов и **ключи первого элемента**.

**`elif isinstance(v, dict)`** для вложенного объекта печатаем его ключи. **`else`** для простых значений печатаем только **тип** (`str`, `int`, `bool`, `NoneType`).

**`f"{k}: ..."`** f-строка: значения в фигурных скобках подставляются в текст. **`sorted(...)`** сортирует ключи для стабильного порядка.

### 6.2 Как читать вывод

| Что видно | Значение |
|---|---|
| `email: str` | Поле есть, значение строка (какая именно, этот скрипт не показывает) |
| `alumnized_at: NoneType` | В JSON стоит `null` |
| `groups: list` (без `[N]`) | Список **пуст** (или состоит не из объектов) |
| `cursus_users: list[3] of dict, keys=[...]` | Три объекта, у первого такие-то поля |
| `staff?: bool` | Поле с вопросительным знаком в имени, это нормально для API 42 |

**Важное ограничение:** `str` не говорит, настоящее ли это значение или заглушка вроде `"hidden"`. Для этого нужен скрипт 4.

## 7. Скрипт 4. Значения без личных данных

Этот скрипт показывает **значения там, где они безопасны** (названия курсов, скиллов, проектов, статусы, числа), а личные поля только **классифицирует**.

```bash
python3 - <<'EOF'
import json, os
from collections import Counter
d = json.load(open(os.path.expanduser("~/goinfre/swifty_samples/user.json")))

def mask(v):
    if v is None: return "None"
    if isinstance(v, str): return "hidden" if v == "hidden" else f"str(len={len(v)})"
    return type(v).__name__

print("== поля профиля ==")
for k in ["email", "phone", "location", "displayname", "pool_month", "pool_year", "kind"]:
    print(k, "->", mask(d.get(k)))
for k in ["wallet", "correction_point"]:
    print(k, "->", type(d.get(k)).__name__)

print("\n== image ==")
img = d["image"]
print("link ->", mask(img.get("link")), "| versions:", sorted((img.get("versions") or {}).keys()))

print("\n== cursus_users ==")
for cu in d["cursus_users"]:
    c, sk = cu["cursus"], cu["skills"]
    print(c.get("name"), "| slug:", c.get("slug"), "| level:", cu["level"], "| grade:", cu["grade"], "| skills:", len(sk), "| end_at:", mask(cu["end_at"]))
    if sk:
        print("   ключи скилла:", sorted(sk[0].keys()))
        for s in sk[:3]:
            print("   ", s.get("name"), s.get("level"))

print("\n== projects_users ==")
pu = d["projects_users"]
print("status:", dict(Counter(p["status"] for p in pu)))
print("validated?:", dict(Counter(p["validated?"] for p in pu)))
print("final_mark None:", sum(p["final_mark"] is None for p in pu))
print("ключи project:", sorted(pu[0]["project"].keys()))
print("с parent_id:", sum(p["project"].get("parent_id") is not None for p in pu))
for p in pu[:3]:
    print("  ", p["project"]["name"], p["status"], p["final_mark"], p["validated?"], "cursus_ids:", p["cursus_ids"])
EOF
```

### 7.1 Разбор

**`def mask(v):`** функция, которая превращает значение в безопасное описание:
- `None` печатает `None`;
- строка равная `"hidden"` печатает `hidden`;
- любая другая строка печатает только её **длину**: `str(len=32)`;
- всё остальное печатает название типа.

Благодаря этому вывод можно спокойно присылать или публиковать: в нём нет почты, телефона и локации.

**Осторожно с длиной.** Слово `hidden` само по себе состоит из 6 символов, поэтому `str(len=6)` не значит «hidden»: заглушку скрипт определяет отдельной проверкой на равенство, как в `mask`.

**`d.get(k)`** безопасное чтение: если ключа нет, вернётся `None`, а не ошибка (в отличие от `d[k]`).

**`(img.get("versions") or {})`** если `versions` отсутствует или пусто, берём пустой словарь, чтобы `.keys()` не упал.

**`for cu in d["cursus_users"]:`** по очереди каждый курс пользователя. **`c, sk = cu["cursus"], cu["skills"]`** сразу распаковывает в две переменные: описание курса и список скиллов.

**`sk[:3]`** срез: первые три элемента (если их меньше, возьмёт сколько есть, без ошибки).

**`Counter(p["status"] for p in pu)`** считает, сколько раз встретилось каждое значение. `dict(...)` превращает счётчик в обычный словарь для печати. Выражение в скобках это *генераторное выражение*: перебор всех проектов с выбором одного поля.

**`sum(p["final_mark"] is None for p in pu)`** в Python `True` равно 1, а `False` равно 0, поэтому сумма логических значений это **количество проектов**, у которых оценка пустая.

## 9. Скиллы и Expertises: это разные вещи

В интре есть два понятия, которые легко спутать.

| | **Skills** (то, что просит задание) | **Expertises** |
|---|---|---|
| Что это | Навыки, которые **начисляются автоматически** за сданные проекты | Области, которые студент **сам отмечает**: «мне интересно» и звёзды 0–5 |
| Где в API | `cursus_users[].skills` | `expertises_users` |
| Поля | `id`, `level` (дробное число), `name` | `contact_me`, `created_at`, `expertise_id`, `id`, `interested`, `user_id`, `value` |
| Название | Лежит прямо в объекте (`name`) | **Нет**: только `expertise_id`, название нужно запрашивать отдельно |
| Пример | «Unix», «Rigor», «Network & system administration» с уровнем вроде 9.63 | «C», «Shell», «Unity» со звёздами |

Как отличить: если в интре ты видишь палец вверх с подписью «You are interested in ...» и пять звёздочек, это **Expertises**. В задании речь о Skills: *«display the user's skills with level and percentage»*, а у Expertises нет ни дробного уровня, ни названия прямо в объекте. Поэтому нам нужны `cursus_users[].skills`.

(Про отдельный запрос названий expertises я знаю по памяти и не проверяла, но для нашего задания он не нужен.)

## 10. Что это значит для приложения

1. **Любое поле может быть пустым.** Модели должны допускать `null` и отсутствие ключей. Пишем разбор JSON так, чтобы одно отсутствующее поле не роняло всё приложение (в Dart это nullable-типы, например `String?`).
2. **Скрытое приходит строкой `"hidden"`.** Нужна одна вспомогательная функция показа, которая превращает `null`, пустую строку и `"hidden"` в «N/A». Так закрывается пункт задания про приватность.
3. **Выбор курса.** Не берём первую запись. Основной курс определяем по `cursus.slug == "42cursus"`. Для студентов, у которых такого курса нет (например, только бассейн), нужен запасной вариант: взять курс с наибольшим уровнем.
4. **Числа.** Уровень разбираем как `num` и приводим к `double`: JSON может отдать `0`, а может `0.0`. Показываем с округлением до двух знаков (из-за шума вида `3.4699999999999998`).
5. **Проекты.** «Завершён» это `status == "finished"`. Сдан или провален определяем по `validated?` (`true`, `false`; возможен `null`). Итоговая оценка тоже может быть пустой.
6. **Фото.** Берём `image.versions.medium`, а если нет, то `image.link`.
7. **Не показываем лишнего.** `anonymize_date`, `data_erasure_date` и подобные служебные поля на экран не выводим.
8. **Скиллы показываем только те, что вернул API.** Остальные категории интры (с нулевым уровнем) в ответе, скорее всего, отсутствуют, поэтому «пустых» скиллов выдумывать не нужно.

## 11. Открытые вопросы

| Вопрос | Статус | Как закроем |
|---|---|---|
| Как считать **процент скилла**? | ⚠️ косвенно подтверждён вариант A | См. ниже |
| Что показывает `location` у студента вне кампуса? | ❓ | Проверить на чужом логине, который сейчас не в кампусе |
| Почему `validated? = true` встречается у проектов не в статусе `finished`? | ❓ | Посмотреть такой проект в интре |
| Показывать ли все завершённые проекты или только основного курса? | ❓ | Решение по заданию («завершённые, включая проваленные»): склоняюсь к показу всех завершённых с отметкой курса |

**Про процент скилла.** В API у скилла есть только `level`, поэтому процент придётся вычислять. Есть две правдоподобные версии:

| Вариант | Формула | Пример для уровня 9.63 | Предпосылка |
|---|---|---|---|
| **A** | `level / 20 × 100` | 48 % | Максимальный уровень скилла равен 20 (по моей памяти, не подтверждено) |
| **B** | Дробная часть уровня | уровень 9, прогресс 63 % | По аналогии с общим уровнем «12.44 → уровень 12, 44 %» (аналогия не подтверждена) |

### 11.1 Проверка по скриншоту радара интры

Мы сверили радар скиллов в интре (скриншот профиля, 17 октября 2026) с числами из API. Измерения сделаны **на глаз по координатам пикселей** на скриншоте, поэтому они приблизительные:

- Радар состоит из 20 осей (по числу категорий скиллов), расположенных по алфавиту по часовой стрелке со смещением 9° от вертикали, и 4 равноотстоящих колец. Радиус внешнего кольца ≈ 308 пикселей.
- Если считать, что внешнее кольцо это уровень 20, то получаем:

| Скилл (из API) | Уровень в API | Длина луча на радаре | Пересчёт `длина / 308 × 20` |
|---|---|---|---|
| Network & system administration | 9.67 | ≈ 149 px | ≈ 9.7 |
| Rigor | 9.63 | ≈ 149 px | ≈ 9.7 |
| Web | 7.28 | ≈ 111 px | ≈ 7.2 |

Направления лучей тоже совпали с положением осей этих скиллов (углы около 9° вправо от низа, 27° под горизонталью слева и 9° влево от верха соответственно).

**Дополнительное подтверждение от пользователя.** Подсказки, которые интра показывает при наведении на концы лучей радара, дают те же значения, что и поле `level` в API: Web 7.28, Rigor 9.63, Network & system administration 9.67. То есть радар в интре строится прямо по `level`, а не по какому-то пересчитанному числу.

**Вывод.** Масштаб радара подтверждает, что максимальный уровень скилла равен 20, то есть вариант A (`level / 20 × 100`) согласуется с тем, как интра сама рисует уровни. Это косвенное подтверждение, а не официальное заявление.

**Чего это не доказывает.** На радаре **нет числового процента**, и в этом экране интры он не показывается вообще. Что именно проверяющие понимают под «percentage», из задания и скриншота не следует. Остаётся небольшой риск, что они ждут вариант B, поэтому остальные шаги в силе.

### 11.2 Что делаем

1. Реализовать процент **одной отдельной функцией**: тогда смена формулы это правка в одном месте.
2. На экране показывать число уровня и процент и **подписать формулу**, например «9.63 / 20 (48 %)». Это защищает на защите, даже если ожидалась другая формула.
3. По возможности уточнить у тех, кто уже сдавал проект (в том числе у проверяющих), как они это понимают.
4. Радар как в интре рисовать необязательно: для задания достаточно списка с индикатором прогресса. Радар можно сделать позже как украшение (своим рисованием без внешних библиотек или готовой библиотекой, которую придётся обосновать на защите).
