## 1. Коротко: команда и результат

Из корня проекта (`~/Projects/swifty-companion`):

```bash
flutter pub get
flutter analyze
flutter test
flutter build apk --release
```

Готовый файл: `build/app/outputs/flutter-apk/app-release.apk`. Напомню, что `build` у нас символическая ссылка на `~/goinfre/swifty_build` ([01, раздел 20.2](01-environment.md)), поэтому файл физически лежит в `goinfre` и пропадёт при чистке. Положи копию туда, где она нужна (на телефон, на флешку, в облако).

Размер на момент нашей сборки на кампусе: **51,6 МБ** (из вывода `flutter build`). Это универсальный APK, внутри которого код под все архитектуры процессора.

## 2. Режимы сборки Flutter: debug, profile, release

| Режим | Команда | Как исполняется Dart-код | Зачем |
|---|---|---|---|
| **debug** | `flutter run` | JIT: код компилируется «на лету» из промежуточного представления | Разработка: hot reload, отладчик, `assert`, подробные ошибки |
| **profile** | `flutter run --profile` | AOT (заранее скомпилирован в машинный код) плюс инструменты измерения | Замер производительности |
| **release** | `flutter build apk --release` или `flutter run --release` | AOT, без отладочной информации, без hot reload | То, что получает пользователь |

**Теория.** В debug-режиме внутри приложения лежит промежуточное представление программы (в нашем debug-APK файл `kernel_blob.bin` весил около 75 МБ без сжатия, это видно в выводе `unzip -l`) и сам компилятор «на лету». Поэтому debug-сборка тяжелее, медленнее и ведёт себя иначе: проверки `assert` включены, виджеты перестраиваются с лишними проверками, `kDebugMode` равен `true`. В release код заранее переведён в машинный (AOT), `assert` выброшены, `kDebugMode` равен `false`.

**Что отсюда следует.** Приложение может работать в debug и вести себя иначе в release. Поэтому перед сдачей release надо один раз пройти руками, а не полагаться на «в debug всё ровно».

Быстрый способ запустить именно release на подключённом телефоне без установки APK вручную: `flutter run --release`. Горячей перезагрузки там нет, но это нормально.

## 3. Что меняется в release у нашего приложения

| Что | В debug | В release | Почему важно нам |
|---|---|---|---|
| `kDebugMode` | `true` | `false` | Весь технический журнал (`GET /v2/users/... → 200`, «Получен токен», `Config loaded`) молчит. Это сделано намеренно: правило проекта «в release тишина» |
| Диагностика при сбое старта | печатается тип ошибки и стек | не печатается | В release при проблеме с конфигом ты увидишь только экран «Ошибка конфигурации», причины в логе не будет. Чтобы разобраться, собери debug |
| Оверлеи и полосы | жёлто-чёрная полоса `OVERFLOWED`, баннер debug | нет | Переполнения в release не видны, но они есть, если есть в debug. Проверяй адаптивность в debug |
| `assert` | работают | выброшены | Не полагайся на `assert` для проверки пользовательских данных (у нас они не нужны: проверки обычные) |
| Разрешение `INTERNET` | берётся из debug-манифеста, если нет в основном | **только из основного манифеста** | Раздел 8, ловушка 1 |
| Сжатие и сокращение кода Android (R8) | выключено | включено, насколько я помню, по умолчанию в шаблоне Flutter | Может «съесть» код, который вызывается через рефлексию. У нас плагинов с рефлексией нет; в проверке из раздела 9 смотрим, что приложение живое |
| Подпись APK | debug-ключ | у нас **тоже debug-ключ** (раздел 6) | Для учебного APK достаточно, для магазина нет |
| Размер | больше (в нём компилятор и промежуточный код) | меньше, у нас 51,6 МБ | Универсальный APK содержит код для всех архитектур |
| Скорость | медленнее, возможны подтормаживания анимаций | быстрее | Заставка, шестерёнки и фото в release выглядят плавнее |

**Про R8.** Как я помню, шаблон Flutter включает сокращение кода для release по умолчанию, но в нашем `android/app/build.gradle.kts` нет ни `isMinifyEnabled`, ни файла правил `proguard-rules.pro`, а я не открывала то, что подставляет Flutter Gradle Plugin. Поэтому как именно собирается наш release по части R8, **не проверено**. Это не мешает собирать и проверять: симптом был бы «в release приложение падает, в debug нет».

## 4. Пошаговая сборка на кампусе

| № | Действие | Зачем и что может пойти не так |
|---|---|---|
| 1 | `flutter --version` | Узнать версию Flutter на этой машине ([01, раздел 4.5](01-environment.md)). Проверено: 3.50.0 |
| 2 | `ls -a ~/goinfre` | Есть ли `flutter`, `androidSDK`, `swifty_build`, `.gradle`. Если пусто, раздел 16 в docs/01 |
| 3 | `ls -ld build` | `build` должна быть ссылкой на `goinfre/swifty_build`, а цель должна существовать. Если нет: `mkdir -p ~/goinfre/swifty_build` ([01, раздел 21.5](01-environment.md)) |
| 4 | Файл `~/goinfre/.gradle/gradle.properties` с лимитами памяти | Иначе сборка может заморозить машину ([01, раздел 20.1](01-environment.md)) |
| 5 | `ls -l .env` | Файл должен существовать (иначе сборка упадёт) и быть заполнен |
| 6 | `flutter pub get && flutter analyze && flutter test` | Не собирать на непроверенном коде. Должно быть `All tests passed!` |
| 7 | `flutter build apk --release` | Первая сборка после пустого `goinfre` долгая (скачиваются зависимости): у нас бывало до 16 минут, последняя debug-сборка заняла 6. Не прерывай |
| 8 | `ls -lh build/app/outputs/flutter-apk/app-release.apk` | Файл есть, размер около 50 МБ |

Во время сборки полезно в соседнем терминале `vmstat 2`: если растёт `si/so` (swap), прерывай сборку раньше, чем зависнет интерфейс ([01, раздел 20.1](01-environment.md)).

## 5. Установка на телефон

```bash
adb devices                                                   # телефон виден как "device"
adb install -r build/app/outputs/flutter-apk/app-release.apk  # -r: заменить, данные сохранить
```

| Симптом | Причина | Решение |
|---|---|---|
| `INSTALL_FAILED_UPDATE_INCOMPATIBLE` | На телефоне стоит версия, подписанная другим ключом | `adb uninstall com.vdarsuye.swifty_companion`, потом установка заново (данных у нас нет, терять нечего) |
| `INSTALL_FAILED_VERSION_DOWNGRADE` | У собранного APK `versionCode` ниже, чем у установленного | Раздел 7: поднять номер сборки или `adb install -r -d` |
| `adb: no devices/emulators found` | Кабель, режим «Передача файлов», отладка по USB не разрешена | Разрешить отладку на телефоне, `adb kill-server && adb devices` |
| Приложение установилось, но «старое» | Установка не прошла, а ты смотришь на прежнюю версию | `adb shell dumpsys package com.vdarsuye.swifty_companion \| grep lastUpdateTime` |

Проверяющему без кабеля: отправить APK файлом. На его телефоне нужно разрешить установку из неизвестного источника для приложения, через которое открывается файл ([14, раздел 8.6](14-remaining-work.md)).

## 6. Подпись: чем debug-ключ отличается от настоящего

**Теория.** Android не устанавливает неподписанный APK. Подпись это цифровая метка, привязывающая приложение к ключу автора; обновление принимается, только если подписано тем же ключом. Поэтому при смене ключа телефон отказывает со словами «`UPDATE_INCOMPATIBLE`».

**У нас сейчас.** В `android/app/build.gradle.kts` стоит (шаблонный) комментарий и строка `signingConfig = signingConfigs.getByName("debug")` для release. То есть release подписан тем же ключом, что и debug: автоматически созданным на машине файлом `~/.android/debug.keystore`.

**Следствия.**

| Следствие | Что это значит |
|---|---|
| Для учебного проекта и показа проверяющему этого достаточно | APK ставится и работает |
| В Google Play такой APK не загрузить | Магазин требует настоящий ключ автора |
| Ключ зависит от машины, где его создали | Мой вывод: `~/.android` лежит в домашней папке, которая общая для всех машин кампуса, поэтому на кампусе ключ, скорее всего, **один и тот же**; а на домашнем компьютере другой. Отсюда `UPDATE_INCOMPATIBLE`, когда ставишь с дома поверх кампусного. Это вывод, не измерение |
| Debug-ключ публично известен по устройству | Любой может подписать подделку тем же ключом. Для магазина критично, для учебной работы нет |

**Проверка, чем подписан APK** (утилита лежит в SDK):

```bash
~/goinfre/androidSDK/build-tools/36.0.0/apksigner verify --print-certs build/app/outputs/flutter-apk/app-release.apk
```

В выводе для debug-ключа я ожидаю строку с `CN=Android Debug`. Версия build-tools в пути должна совпадать с установленной (`ls ~/goinfre/androidSDK/build-tools`). Ожидаемый вывод **не проверялся**.

**Как сделать настоящую подпись (если понадобится; в учебном проекте не делаем).**

1. Создать ключ: `keytool -genkey -v -keystore ~/upload-keystore.jks -keyalg RSA -keysize 2048 -validity 10000 -alias upload`. Вне репозитория, пароль запомнить.
2. В `android/key.properties` записать пути и пароли, **добавить файл в `.gitignore`**.
3. В `build.gradle.kts` описать `signingConfigs` и подключить к release.
4. Хранить ключ в безопасном месте: потерял ключ, больше не обновишь приложение в магазине.

Шаги 3 и 4 описаны в документации Flutter («Build and release an Android app»); сам Gradle-блок для нашей конфигурации (в проекте стоят флаги `android.newDsl=false` и `android.builtInKotlin=false`) я не проверяла, поэтому не привожу его здесь.

## 7. Версия приложения: `version: 1.0.0+1`

В `pubspec.yaml`: `version: 1.0.0+1`. До плюса `versionName` (то, что видит человек), после плюса `versionCode` (число, по которому Android сравнивает версии).

| Ситуация | Что произойдёт |
|---|---|
| Ставишь APK с тем же `versionCode` поверх (`-r`) | Принимается, если подпись та же |
| С меньшим `versionCode` | `INSTALL_FAILED_VERSION_DOWNGRADE` |
| Хочешь, чтобы по версии было видно, какая сборка | Поднимай номер после плюса: `1.0.0+2` |

Для защиты разумно перед финальной сборкой поднять номер и коммитить это отдельным коммитом с понятным сообщением. Это не обязательно.

## 8. Ловушки, которые нас уже кусали

| № | Ловушка | Что было | Что делать |
|---|---|---|---|
| 1 | **`INTERNET` только в debug** | Flutter кладёт это разрешение только в debug- и profile-манифесты. Без строки в основном манифесте release-приложение не имеет сети: в debug всё работает, в release «нет сети» | У нас строка есть в `android/app/src/main/AndroidManifest.xml` ([07, раздел 8](07-token-service.md)). Если проект пересоздадут (`flutter create`), проверь, что она не пропала |
| 2 | **`.env` не попал в APK** | 12 ноября на Flutter 3.50.0 файл `.env` был в `flutter_assets` при сборке, но не в APK, и приложение показывало экран ошибки ([05, раздел 3.1](05-config-and-skeleton.md)) | В `android/app/build.gradle.kts` добавлен `ignoreAssetsPattern` без `.*`. Каждый раз проверяй: `unzip -l app-release.apk \| grep -i env` |
| 3 | Первая сборка зависла и заморозила комп | Gradle по умолчанию просит до 8 ГБ памяти | [01, раздел 20.1](01-environment.md) |
| 4 | `flutter clean` и пропавшая `build` | `clean` удаляет ссылку | [01, раздел 20.2](01-environment.md) |
| 5 | Другая версия Flutter на другой машине | AGP 9.1.0 слишком старый для 3.50, предупреждения об устаревших импортах | [01, раздел 4.5](01-environment.md), [17](17-material-ui-migration.md) |
| 6 | Изменённый `pubspec.lock` в `git status` | Версия Flutter другая | [02, раздел 13](02-git-and-secrets.md) |
| 7 | В APK лежит секрет | `.env` это ассет, а APK это zip, секрет достаётся архиватором | [14, раздел 8.2](14-remaining-work.md): перегенерировать секрет после показа или завести отдельное демо-приложение в интре |

## 9. Чек-лист перед сдачей

Отмечай галочкой. Каждый пункт делается на **release-APK**, а не на debug.

| № | Проверка | Ожидаемый результат | ✅ |
|---|---|---|---|
| 1 | `flutter analyze && flutter test` | Чисто, `All tests passed!` | ☐ |
| 2 | `flutter build apk --release` | `✓ Built build/app/outputs/flutter-apk/app-release.apk` | ☐ |
| 3 | `unzip -l build/app/outputs/flutter-apk/app-release.apk \| grep -i env` | Строка `assets/flutter_assets/.env` | ☐ |
| 4 | `adb install -r ...app-release.apk` | `Success` | ☐ |
| 5 | Запуск: заставка, поиск | Нет экрана «Ошибка конфигурации» | ☐ |
| 6 | Поиск своего логина | Профиль с фото, скиллами, проектами (значит, сеть и токен работают в release) | ☐ |
| 7 | Чужой профиль, несуществующий логин, пустое поле, недопустимые символы | Сообщения, как в [14, раздел 3](14-remaining-work.md) | ☐ |
| 8 | Авиарежим и «Поиск» | «Нет сети», без падения | ☐ |
| 9 | Поворот, максимальный шрифт | Ничего не вылезает ([14, раздел 4](14-remaining-work.md)) | ☐ |
| 10 | `adb logcat \| grep -i flutter` во время работы | Нет строк `GET /v2/...`, `Получен токен` и подобных (в release мы молчим); **главное: нет токена и секрета** | ☐ |
| 11 | Язык телефона: испанский и английский | Надписи переводятся, в диалогах копирования тоже | ☐ |
| 12 | `git status` | Нет `.env`, `build/`, ключей | ☐ |
| 13 | Аудит секретов ([14, раздел 8.1](14-remaining-work.md)) | Пусто, где должно быть пусто | ☐ |
| 14 | Размер и путь APK записаны | Для себя и для отчёта | ☐ |

Пункт 10 важный: в release журнал не должен ничего печатать. Если что-то печатается, значит, где-то `print` или `debugPrint` без `kDebugMode`.

## 10. Альтернативы и опциональные флаги

| Вариант | Команда | Плюсы | Минусы |
|---|---|---|---|
| **Универсальный APK (наш выбор)** | `flutter build apk --release` | Один файл, работает на любом Android от `minSdk` | Больше (51,6 МБ), в нём код под все архитектуры |
| APK под архитектуры | `flutter build apk --release --split-per-abi` | Три файла поменьше | Надо выбрать правильный: современному телефону нужен `arm64-v8a`; не тот не поставится |
| Android App Bundle | `flutter build appbundle` | Формат для Google Play, магазин сам выдаёт нужный набор | Напрямую на телефон не ставится, магазин нам не нужен |
| Обфускация Dart-кода | `flutter build apk --release --obfuscate --split-debug-info=<папка>` | Названия классов в APK нечитаемы | Стеки ошибок нечитаемы без папки с символами; **на секрет не влияет**, он остаётся в ассете открытым текстом |
| Анализ размера | `flutter build apk --release --analyze-size` | Видно, из чего состоят 51,6 МБ | Дополнительный вывод, в готовый файл ничего не добавляет |
| Сборка в CI | GitHub Actions и подобное | Воспроизводимо, не грузит машину кампуса | Секрет надо хранить в настройках CI; для учебного проекта избыточно |
| Сборка дома | та же команда | Мощнее компьютер, не зависит от `goinfre` | Другой debug-ключ ([раздел 6](#6-подпись-чем-debug-ключ-отличается-от-настоящего)); версия Flutter может отличаться |

Про обфускацию отдельно, потому что на защите любят спросить «а секрет защищён?». Нет: он лежит в ассете, и обфускация кода его не трогает. Честный ответ: это учебный проект, APK раздаётся ограниченному кругу, секрет можно перегенерировать ([14, раздел 8.2](14-remaining-work.md)).

## 11. Риски

| Риск | Чем грозит | Снижение |
|---|---|---|
| Сдавать APK, собранный только в debug-проверке | Release мог повести себя иначе (сеть, R8, конфиг) | Чек-лист из раздела 9 на release-APK |
| Забыть про `INTERNET` после пересоздания проекта | В release нет сети при полностью рабочем debug | Пункт 6 чек-листа |
| Собирать в последний день перед защитой на пустом `goinfre` | Долгая первая сборка (до 16 минут) и риск, что что-то не поставится | Собрать заранее, держать копию APK вне `goinfre` |
| Новая версия Flutter у проверяющего | Могут поднять минимумы инструментов или убрать устаревшее | Держать проект на актуальных версиях; указать в README версию, на которой проверено |
